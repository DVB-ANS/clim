# Session log · 2026-10-06 (clim-front)

This repo is plan 05's `app/` (the repo root = `app/`); it is copied as is into `clim/app/`. Decisions, deviations from plan 05 and surprises, with the same headings as `clim/docs/sessions/2026-10-06.md`, so the lines can be merged there.

## Decisions
- **Frontend stack (plan 05):** Next.js 16.3.8 (App Router, Turbopack), React 19.2, Tailwind 4, Recharts 3.10 for charts, viem 2.57 only (no wagmi: the optional test-swap page needs one injected wallet), Vitest 5 for the pure transforms. *(The "viem only" part is superseded by the Frontend scope upgrade: see "Wallet stack" below.)* `npm run sync` copies shared/, lab/out and docs/faq.md into app/, so Vercel builds app/ alone.
- **Execution of plan 05 in this repo:** paths lose their `app/` prefix and commands run at the root; file, type and function names are the plan's. `main` restarts from plan 05's Task 1: the earlier build to the first brief (layout `app/`, `lib/`, `components/` at the root, simulation-based mock) is kept in the local tag `archive/brief-layout`, not pushed.
- **Design tokens (deviation from plan 05's code, by the maintainer's brief):** every colour, radius and font lives in `src/app/globals.css` (CSS variables, exposed to Tailwind with `@theme inline`; Tailwind's default palette is switched off) and in `src/lib/theme.ts` (chart series and hook modes mapped to those variables). Components use token utilities (`bg-surface`, `text-fg-muted`, `border-line`, `text-link`, ...) where the plan wrote raw Tailwind colours (`bg-white`, `text-neutral-500`, `bg-amber-50`, ...). Plan 05's entity colours are kept as the default values (V `#2a78d6`, S `#eb6834`, σ `#1baf7a`). `src/lib/theme.ts` keeps the plan's `COLORS` and `MODE_STYLE` but its values are `var(--clim-…)` references; it adds three roles (`ink`, `blind`, `surface`) for the hex literals the plan's components wrote inline (`#52514e`, `#d03b3b`, `#fff`). One script maps the plan's classes to tokens in every component, and each component's diff against the plan is reviewed to contain styling only.
- **Wallet stack (Frontend scope upgrade):** RainbowKit 2.2.11 declares `wagmi ^2.9.0` as peer, and wagmi is at 3.7.7, so RainbowKit is paired with wagmi 2 (its supported major): one kit and one wagmi config. Injected wallets work without a WalletConnect projectId; WalletConnect wallets are added only when `NEXT_PUBLIC_WC_PROJECT_ID` is set. (Reown AppKit supports wagmi 3 but needs a projectId to run, which would have required a second, injected-only code path.)
- **Lab outputs read by the app (plan 05):** `lab/out/summary.json` and the columnar part of `lab/out/replay-2026-02-04.json` (plus an optional `price[]` in the replay), written by plan 03, and `lab/out/ptrade-band.json` (`{generatedAt, windowBlocks, method, grid[{p, lo95, hi95, lo99, hi99}]}`), typed in `app/src/lib/lab.ts`. Plan 03 writes exactly these.
- **Arbitrage identification (plan 05):** the dashboard counts a swap as arbitrage when `Swap.sender == routers.arb` in shared/deployments/sepolia.json. The arbitrage bot therefore swaps through its own PoolSwapTest instance, used by nothing else (plans 01 and 04).
- **`CLIM_ROOT` for `npm run sync` (addition to plan 05's Task 13 entry point):** while the app is a separate checkout (clim-front), `CLIM_ROOT=../clim npm run sync` reads the clim repo next to it; without it the default stays the plan's (the parent directory, i.e. the clim repo once the app is `clim/app`). The committed `src/generated/faq.ts` comes from `clim/docs/faq.md` this way; `sepolia.json`, `params.json` and the lab files are still fixtures (no `shared/` or `lab/out/` yet).
- **Dashboard on mock data (plan 05):** all panels run on a deterministic mock chain whose logs are ABI-encoded like the real ones, so switching to Sepolia changes only the data source (automatic once the live desk, hook and pools are in shared/deployments/sepolia.json; `NEXT_PUBLIC_CLIM_SOURCE=mock` forces mock data).

Mock data until the contracts are deployed; redeploy with `vercel deploy --prod --yes` after every `npm run sync`. ## Surprises
- **Sepolia RPC log history (plan 05):** publicnode serves `eth_getLogs` only for about the last 10,000 blocks ("pruned history unavailable") and caps ranges at 50,000 blocks; Tenderly's public gateway (https://sepolia.gateway.tenderly.co) serves full history. The dashboard uses Tenderly first, publicnode as fallback, 5,000-block chunks, and a frozen log snapshot before submission. Bots and scripts that scan old logs should not rely on publicnode.
- **Retail noise inflates observed P_trade (plan 05 mock):** retail orders whose price impact approaches the fee floor create extra arbitrage blocks ($3k orders on $2M of full-range TVL: observed 0.64 vs predicted 0.20; $500 orders on $20M: 0.21 vs 0.195). Plan 04's pool depth (L about 5.2e23, a $2,000 order moves the price about 0.15 bp) keeps this effect small; keep it that way, or the live validation chart will look wrong for a reason unrelated to the model.
- **Correction to the line above (clim-front):** at L about 5.2e23 the pool holds about $27M per side at $2,700, so a $2,000 order moves the price by 2 x 2,000 / 27M = about 1.5 bp, not 0.15 bp. That is half the per-block volatility at 50%/yr (about 3 bp): plan 04's noise bot can still lift the observed P_trade above the model in calm markets. A simulation run earlier in this session (tag `archive/brief-layout`) measured observed 0.31 against 0.21 predicted in calm with $2,000 swaps every two blocks, and 0.22 against 0.21 with $250 swaps. Worth a look in plan 04 before reading the live validation chart.
- **Vercel could not connect the GitHub repo:** `vercel link` created and linked the project but failed to connect DVB-ANS/clim-front (the Vercel GitHub app has no access to the private DVB-ANS repos). CLI deployments work without it; to deploy on push, grant the Vercel app access to the DVB-ANS organisation (then to DVB-ANS/clim after the merge).
- **Optional `@x402/*` peers broke the SSR build:** RainbowKit imports wagmi's `baseAccount` connector; on the server, `@base-org/account` loads its Node entry, which pulls `@coinbase/cdp-sdk` and its lazy `import("@x402/...")` of optional peers, and Turbopack fails on the missing modules. `serverExternalPackages: ["@base-org/account", "@coinbase/cdp-sdk"]` in `next.config.ts` loads them from node_modules on the server instead (the lazy imports stay lazy); the browser bundle is unaffected.
